All three bands: same source `src=0/32/4x/c3`, same `sample_select=00000006`.
Bands 1 and 2 use the **identical rect `0,0-1280,256`**; band 3 uses `0,0-1280,208`.
Dest bases step by exactly 1,310,720 bytes (1280×256×4) per band:

**What this proves (Rank 1, confirmed at runtime):** all three bands resolve the SAME
source rows (0–256) but write to three successive dest regions. The dest side
advances correctly; the source side never advances. So the frontbuffer gets three
copies of the same 256 source rows stacked at dest rows 0–256, 256–512, 512–720,
and the real scene rows 256–720 are never read. This is the duplication/banding
mechanism, observed live — not inferred from code alone.
